# 增量更新流程 v3.0

> 当新信息出现时，低成本更新已有Skill

## 触发条件

以下情况需要增量更新：
1. **用户提供新素材** - 用户提供了新的书籍、访谈、决策记录
2. **此人发表新观点** - 新的公开演讲、文章、访谈
3. **发现遗漏信息** - 发现之前遗漏的重要信息
4. **定期更新** - 每6-12个月检查一次

---

## 增量更新流程

### Step 1: 识别更新类型

```markdown
## 更新类型判断

### 类型A: 新素材补充
- 用户提供了新的书籍/访谈/决策记录
- 处理: 分析新素材，更新受影响的维度

### 类型B: 新观点发表
- 此人发表了新的公开观点
- 处理: 检查是否影响现有心智模型

### 类型C: 遗漏信息
- 发现之前遗漏的重要信息
- 处理: 补充到对应Agent输出

### 类型D: 立场转变
- 此人明确改变了某个观点
- 处理: 更新心智模型的时效状态
```

### Step 2: 确定影响范围

```markdown
## 影响范围评估

### 检查清单
- [ ] 新信息属于哪个维度？（著作/对话/表达/他者/决策/时间线）
- [ ] 是否影响现有心智模型？
  - 是 → 更新心智模型
  - 否 → 只补充来源
- [ ] 是否导致矛盾？
  - 是 → 记录为时间性矛盾或本质性张力
  - 否 → 正常更新

### 影响分类
| 影响类型 | 处理方式 |
|---------|---------|
| 补充信息（无矛盾） | 直接添加到对应Agent输出 |
| 立场转变（有时间标记） | 记录为时间性矛盾，更新时效状态 |
| 新心智模型（三重验证通过） | 添加到心智模型列表 |
| 放弃旧模型（明确声明） | 标注为"❌已放弃" |
```

### Step 3: 执行更新

```markdown
## 更新步骤

### 1. 添加新素材
将新素材添加到 `sources/` 对应子目录：
- 书籍 → `sources/books/`
- 访谈 → `sources/transcripts/`
- 文章 → `sources/articles/`

### 2. 重跑受影响的Agent
只重跑受影响的Agent，不需要全部重跑：
```bash
# 例如：新素材是对话，只重跑Agent 2
python3 scripts/run_agent.py --agent 02-conversations --update
```

### 3. 更新research文件
将新发现写入对应的 `01-writings.md` 到 `06-timeline.md`

### 4. 重新运行质量门禁
```bash
python3 scripts/quality_gate.py [skill目录]
```

### 5. 更新SKILL.md
根据新发现更新SKILL.md：
- 新增心智模型？ → 添加到"心智模型"section
- 立场转变？ → 更新"演化轨迹"
- 新决策？ → 添加到"决策启发式"

### 6. 标注更新日期
在SKILL.md开头添加：
```markdown
最后更新: [日期]
更新内容: [简述更新了什么]
```

### 7. 重新测试
运行Phase 4测试，验证更新后的Skill：
- [ ] 已知测试（3个）
- [ ] 边缘测试（1个）
- [ ] 风格测试（1个）
```

## 示例：更新芒格Skill

### 场景：芒格发表新演讲（2025年）

```markdown
## 增量更新记录

### 更新类型
类型B: 新观点发表

### 新信息
- 芒格在2025年BERKSHIRE年会发表新演讲
- 新增了"AI泡沫"的观点

### 影响评估
- 影响维度: Agent 1（著作）+ Agent 2（对话）
- 影响心智模型: 不影响现有模型，但新增一个观点
- 是否矛盾: 否（与"逆向思维"一致）

### 更新操作
1. 添加演讲transcript到 `sources/transcripts/2025-berkshire.md`
2. 重跑Agent 1和Agent 2
3. 更新 `01-writings.md` 和 `02-conversations.md`
4. 在SKILL.md中添加：
   ```markdown
   ## 近期观点（2025）
   - AI泡沫: "现在的AI热让我想起了1999年的互联网泡沫"
   ```
5. 更新日期标注：最后更新 2025-06-15
6. 重新测试：3/3已知测试通过 ✅
```

## 版本管理

### SKILL.md版本标注
在SKILL.md开头添加版本信息：

```markdown
# [人名] 视角

**版本**: v1.2
**创建时间**: 2024-01-15
**最后更新**: 2025-06-15
**更新历史**:
- v1.2 (2025-06-15): 添加2025年BERKSHIRE新观点
- v1.1 (2024-06-01): 补充Agent 5决策记录
- v1.0 (2024-01-15): 初始版本
```

### Git版本控制
如果Skill目录是git仓库：
```bash
cd [skill目录]
git add .
git commit -m "update: 添加2025年新观点"
git tag v1.2
```

## 定期更新建议

```markdown
## 定期更新计划

### 每季度检查（每3个月）
- [ ] 搜索此人最近3个月的新观点
- [ ] 检查是否有立场转变
- [ ] 更新"近期动态"section

### 每年大更新（每12个月）
- [ ] 重跑所有Agent（如果有足够新素材）
- [ ] 重新验证心智模型
- [ ] 更新"思想演化"section
- [ ] 重新运行所有测试

### 触发更新
- 用户提供了新素材 → 立即更新
- 此人发表重要观点 → 立即更新
- 发现重大遗漏 → 立即更新
```

## 更新成本估算

| 更新类型 | 预计耗时 | 重跑Agent |
|---------|---------|----------|
| 补充少量信息 | 15-30分钟 | 1个 |
| 新增观点 | 30-60分钟 | 1-2个 |
| 立场转变 | 1-2小时 | 2-3个 |
| 年度大更新 | 2-4小时 | 全部6个 |
